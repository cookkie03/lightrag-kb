# LightRAG-KB

Minimal CLI to manage local LightRAG knowledge bases with:

- WebUI as the primary surface for humans
- Query-only MCP for coding agents
- A single shared Python runtime for `ragcli`, `lightrag-server`, LightRAG, Docling, and OAuth shim
- Incremental ingestion from the real source directory

## Operating Model

For each KB:

- `source_dir` contains the original files to be indexed
- `source_dir/.lightrag/rag_storage/` contains LightRAG internal storage
- `source_dir/.lightrag/derived/` contains Docling artifacts generated by the pipeline

Standard layout:

```text
<source_dir>/.lightrag/
  .env
  derived/
    text/
    pdf/
    images/
    office/
    audio/
    cache/
    manifests/
  rag_storage/
```

The server always starts with:

```bash
lightrag-server --input-dir <source_dir> --working-dir <source_dir>/.lightrag/rag_storage --port <port>
```

`ragcli start` is the only CLI command that starts the server. `ingest` and MCP do not auto-start.

## Setup

After cloning:

```bash
./setup.sh
```

The script:

1. creates `.venv`
2. installs `lightrag-hku[api]`, `ollama`, Docling, MCP dependencies, and OAuth shim dependencies into it
3. creates symlinks:
   - `~/.local/bin/ragcli`
   - `~/.local/bin/lightrag-server`
4. creates `config/global.env` from `config/global.env.example` if missing
5. on Linux, installs `systemd --user` units and publishes the shim via `tailscale funnel`

## Linux Bootstrap

Recommended workflow on Linux:

```bash
./setup.sh
ragcli doctor
ragcli service status
```

`setup.sh` sets up the shared runtime, synchronizes central configuration (`config/global.env`), installs the repo's `systemd --user` units, and configures `tailscale funnel` to publicly expose the OAuth shim.

To also start the public MCP backend on Linux, set `PUBLIC_MCP_KB=<kb-name>` in `config/global.env`: the bootstrap enables `lightrag-server@`, `lightrag-watchdog@`, `lightrag-mcp@`, and then the OAuth shim that exposes them via Tailscale.

## Public CLI

```bash
ragcli doctor
ragcli add <name> <source_dir> [--port]
ragcli list
ragcli ingest <name> [--force]
ragcli exclude add <name> <pattern>
ragcli exclude rm <name> <pattern>
ragcli start <name>
ragcli stop <name>
ragcli remove <name>
ragcli mcp add <name> --client <client|all>
ragcli mcp rm <name> --client <client|all>
ragcli move <name>
ragcli service status [service-name]
ragcli service restart [service-name]
ragcli service logs [service-name]
```

Quick example:

```bash
ragcli add project ~/code/my-project
ragcli start project
ragcli ingest project
ragcli mcp add project --client codex
```

WebUI: `http://127.0.0.1:<port>`

`ragcli remove <name>`:

- requires the server to be stopped
- removes the KB from the registry
- deletes the entire `data_dir` (including `.lightrag/`, `derived/`, `rag_storage/`, `.env`, logs, and cache)
- attempts to unregister the MCP from supported clients
- completely preserves `source_dir` and the original files

## Ingest

`ragcli ingest <name>`:

- synchronizes the KB's local `.env` with global configuration first
- discovers candidates from `source_dir`
- executes render and insert as separate phases
- for text/code, uses original content directly
- for PDF and images, uses Docling with high-quality profile consistent with `DOCLING_PLATFORM`
- for Office, ODF, EPUB, EML, MSG, uses native Docling parsing
- for audio/video, uses Docling ASR consistent with `DOCLING_PLATFORM`
- saves derived artifacts under `derived/...`
- uses a phase-aware manifest to skip unnecessary rerenders and only retry failed inserts
- attempts inserts in a stable order: text, office, PDF/images, audio/video
- maintains incremental sync with pruning of deleted files

`ragcli ingest <name> --force`:

- regenerates derived artifacts
- rebuilds local manifests and cache
- forcibly realigns the KB with the source

## Docling

Configuration is centralized in `config/global.env`. The main selector is `DOCLING_PLATFORM`:

- `linux` for local or remote Linux runtimes
- `mac` for Apple Silicon/macOS
- `auto` to derive it from the operating system

`DOCLING_OCR_ENGINE`, `DOCLING_ASR_ENGINE`, and `DOCLING_ACCELERATOR` remain available as explicit overrides, but are no longer the primary configuration point.

Ingest formats remain unchanged. PDF/images use Docling with table structure enabled; Office, ODF, EPUB, EML, and MSG use native Docling parsing; audio/video use Docling ASR.

## Docling on macOS

The profile used in the repo is aligned with official Docling documentation:

- `OcrMacOptions(recognition="accurate")`
- `force_full_page_ocr=True` only when native text probing is degraded, or for images
- `do_table_structure=True`
- `TableFormerMode.ACCURATE`
- `do_cell_matching=True`
- `images_scale=2.0`
- `do_formula_enrichment=True`
- `do_code_enrichment=True`
- `AcceleratorDevice.MPS`
- ASR `WHISPER_TURBO_MLX` on Apple Silicon

Official references:

- [Installation](https://docling-project.github.io/docling/getting_started/installation/)
- [Advanced options](https://docling-project.github.io/docling/usage/advanced_options/)
- [Supported formats](https://docling-project.github.io/docling/usage/supported_formats/)
- [Processing audio and video](https://docling-project.github.io/docling/usage/processing_audio_media/)
- [GPU support](https://docling-project.github.io/docling/usage/gpu/)

Note: updated documentation indicates ODF (`.odt`, `.ods`, `.odp`) is supported natively by Docling, so it is no longer treated as a format requiring upfront conversion.

## MCP

`mcp/lightrag_mcp.py` exposes 3 tools:

- `ask`
- `retrieve_context`
- `find_documents`

If the server is stopped, the MCP will not attempt to start it and will return an explicit message directing to `ragcli start <name>`.

## Global Configuration

`config/global.env` controls the shared runtime and global parameters for LightRAG and Docling.

Primary variables:

- `ENGINE_PYTHON`
- `LIGHTRAG_SERVER_BIN`
- `DOCLING_PYTHON`
- `DOCLING_LANG`
- `DOCLING_TIMEOUT`
- `LLM_PROVIDER`
- `OLLAMA_HOST`
- `LLM_MODEL`
- `EMBEDDING_MODEL`
- `BASE_PORT`
- `MCP_BIND_HOST`
- `MCP_BIND_PORT`
- `MCP_PATH`
- `PUBLIC_MCP_KB`
- `SHIM_BIND_HOST`
- `SHIM_BIND_PORT`
- `TAILSCALE_FUNNEL_PORT`
- `SHIM_PUBLIC_URL`

## OAuth Shim

The shim uses OAuth and on Linux runs under `systemd --user`, bound locally to `127.0.0.1`, and is published to the internet via `tailscale funnel`. The final public URL is configured in `SHIM_PUBLIC_URL`; the bootstrap script automatically derives it from `tailscale status --json` when the initial placeholder is found.

The actual backend behind the shim is `mcp/lightrag_mcp.py`, exposed via `streamable-http` on `MCP_BIND_HOST:MCP_BIND_PORT` and configured in the shim as `LIGHTRAG_MCP_URL`.
